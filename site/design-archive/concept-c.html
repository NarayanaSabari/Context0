B-02 / RETRIEVAL
Design argument

Similarity finds mentions. Relationships find the truth.

A flat vector index cannot tell an old fact from a current one. Kora stores memory as a connected model, then combines graph traversal with vector similarity.

B-02.1

Traditional vector DB

Three similar chunks. No state.

Every database mention comes back ranked by cosine similarity, including the outdated one.

C-03 / FAILURE MODES

Agents are amnesiac by default.

CASE / 02

A support bot asks the same onboarding questions every time a returning customer reaches out.

CASE / 03

Your team runs five AI tools on one project. None of them share what they learned.

F-06 / DATA MODEL
Schema view

Memory is typed. Change is an edge.

Facts do not pile up as anonymous chunks. Kora keeps their type and the relationships between them explicit.

Typed node / edge model

A data model that knows what changed, and why.

Contradiction detection marks stale facts as superseded instead of leaving old and new claims to compete in retrieval.

G-07 / CAPABILITIES
Core functions

A durable memory layer for every agent.

Feed it interactions, retrieve focused context, and maintain project-level profiles without locking memory to one model or application.

FN-01

Remember everything

Feed it any conversation. It extracts the facts, preferences, and events automatically and stores them as typed nodes.

FN-02

Recall what matters

Not 50 vaguely related chunks. The 3-5 memories that actually answer the question, with the relationships that explain them.

FN-03

Build user profiles

A static profile for role, expertise, and preferences plus a dynamic profile for the last 7 days of events, maintained automatically per project.

H-08 / INTERFACE
REST surface

Real API. Ten precise entry points.

Store, extract, connect, query, inspect, and delete memories through a compact REST surface. Use the Python SDK or call the service directly.

Python / query example
from kora import KoraClient

client = KoraClient(
  endpoint="localhost:50051",
  api_key=...,
  project="my-project"
)

client.extract(
  "user: We switched to PostgreSQL\n"
  "user: I prefer vim"
)

results = client.query(
  "what database does this project use?",
  top_k=3
)

I-09 / DEPLOYMENT
Install paths

Run the whole memory substrate yourself.

Start locally with Docker Compose or deploy into your Kubernetes cluster with Helm. Your data stays on your infrastructure.

Docker Compose
# Generate credentials
cat > .env <<EOF
POSTGRES_PASSWORD=$(openssl rand -hex 16)
KORA_API_KEYS=$(go run ./cmd/cli keys generate)
EOF

docker compose up
Helm / Kubernetes
# Install into your cluster
helm install kora ./charts/kora \
  -n kora --create-namespace \
  --set postgres.existingSecret=\
my-postgres-secret \
  --set auth.existingSecret=\
my-api-keys
