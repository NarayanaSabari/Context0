The problem

Every memory node here exists. None of them are connected.

That's the failure mode, illustrated: isolated facts nobody can follow back to the conversation that produced them.

01

You explain your architecture to your coding assistant on Monday. On Tuesday it has no idea what you said.

02

A support bot asks the same onboarding questions every time a returning customer reaches out.

03

Your team runs five AI tools on one project. None of them share what they learned.

Why existing approaches fall short

Three ways teams patch this today. None of them fix it.

Platform memory

ChatGPT, Claude — locked to one vendor, cannot be shared across tools.

Vector databases

Find similar text, but do not understand relationships between memories.

Custom solutions

Every team rebuilds the same thing, poorly, again.

What it does

Watch the graph knit itself together

Every capability below is one more edge drawing itself into the graph behind this page.

Remember everything

Feed it any conversation. It extracts the facts, preferences, and events automatically and stores them as typed nodes.

Recall what matters

Not 50 vaguely related chunks. The 3–5 memories that actually answer the question, with the relationships that explain them.

Build user profiles

A static profile (role, expertise, preferences) plus a dynamic one (last 7 days of events), maintained automatically per project.

The centerpiece

The old fact isn't deleted. It's superseded.

Real API, real code

Not a mockup. This runs.

extract.sh
curl -X POST http://localhost:8080/v1/memories/extract \
  -H "X-API-Key: $API_KEY" \
  -d '{"conversation": "user: We switched from MySQL to
       PostgreSQL last week because we needed graph
       support", "project_id": "my-project"}'
client.py
from context0 import Context0Client

client = Context0Client(endpoint="localhost:50051", api_key=..., project="my-project")

client.extract("user: We switched to PostgreSQL\nuser: I prefer vim")
results = client.query("what database does this project use?", top_k=3)
One database, one query path. Apache AGE and pgvector live in the same PostgreSQL instance, so graph traversal and vector search happen together — no sync between two stores.

Install

Running in your cluster in minutes

Docker Compose
# .env
cat > .env <<EOF
POSTGRES_PASSWORD=$(openssl rand -hex 16)
CONTEXT0_API_KEYS=$(go run ./cmd/cli keys generate)
EOF
docker compose up
Helm
helm install context0 ./charts/context0 \
  -n context0 --create-namespace \
  --set postgres.existingSecret=my-postgres-secret \
  --set auth.existingSecret=my-api-keys
pip install context0 context0 store context0 query context0 graph <id> --depth 2
