The important difference

Similarity is not memory.

A vector database can find every sentence that mentions a database. It cannot tell you which fact is current, what it replaced, or why the decision changed.

Kora stores a connected graph, then combines relationship traversal with vector similarity. It brings back an answer with its history attached.

What Kora does

Turn a transcript into a memory system.

Not a longer prompt. A durable, queryable layer that knows the difference between an old fact and the reason it changed.

01

Remember everything

Feed it any conversation. It extracts the facts, preferences, and events automatically and stores them as typed nodes.

02

Recall what matters

Not 50 vaguely related chunks. The 3-5 memories that actually answer the question, with the relationships that explain them.

03

Build user profiles

A static profile - role, expertise, preferences - plus a dynamic one - last 7 days of events - maintained automatically per project.

One query path

Graph and vector, in the same place.

Apache AGE and pgvector live in the same PostgreSQL instance. Graph traversal and vector search happen in one database, one query path, with no sync between two stores.

Real interface

No hand-waving. Just an API.

Extract a conversation, then ask for the memories that matter. The same engine is available through REST and the Python SDK.

extract-and-query.py
from kora import KoraClient

client = KoraClient(endpoint="localhost:50051", api_key=..., project="my-project")

client.extract("user: We switched to PostgreSQL\nuser: I prefer vim")
results = client.query("what database does this project use?", top_k=3)
